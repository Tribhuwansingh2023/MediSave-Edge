# Redistribution Engine Architecture

## Overview
The **Redistribution Decision Support Engine** in **MediSave Edge** analyzes distributed healthcare inventory datasets and formulates re-allocation proposals to resolve medicine shortages while leveraging regional surpluses.

```
                      +-----------------------------+
                      | Distributed Facility Nodes  |
                      |   (TCP Updates / Local)     |
                      +-----------------------------+
                                     |
                                     v
                      +-----------------------------+
                      |   Stock Classification     |
                      | (SHORTAGE, NORMAL, SURPLUS) |
                      +-----------------------------+
                                     |
                                     v
                      +-----------------------------+
                      |   Surplus / Shortage Delta  |
                      |   Surplus  = Qty - MinReq   |
                      |   Shortage = MinReq - Qty   |
                      +-----------------------------+
                                     |
                                     v
                      +-----------------------------+
                      |      Medicine Matching      |
                      | (ID, Name, Compatible Batch)|
                      +-----------------------------+
                                     |
                                     v
                      +-----------------------------+
                      |     Transfer Quantity       |
                      |  min(Surplus, Shortage)     |
                      +-----------------------------+
                                     |
                                     v
                      +-----------------------------+
                      | Redistribution Advisory     |
                      |       Recommendation        |
                      +-----------------------------+
```

---

## 1. Stock Classification Model
Each facility reports stock for a specific medicine record according to the `FacilityStock` structure:

```cpp
struct FacilityStock {
    std::string facilityName;
    std::string medicineId;
    std::string medicineName;
    std::string batchNumber;
    int quantity;
    int minimumRequired;
    int maximumCapacity;
    std::string expiryDate;
};
```

Stock classification is performed deterministically:
* **SHORTAGE**: `quantity < minimumRequired`  
  Shortage delta: `shortage = minimumRequired - quantity`
* **NORMAL**: `minimumRequired <= quantity <= maximumCapacity`
* **SURPLUS**: `quantity > maximumCapacity` (or in redistribution balancing: `quantity > minimumRequired`)  
  Available surplus: `surplus = quantity - minimumRequired`

---

## 2. Deterministic Matching & Priority Logic
When multiple facilities report imbalances, recommendations are formed using deterministic, reproducible priority ordering:

1. **Shortage Severity First**: Facilities with the highest shortage quantity are evaluated first (`destinationShortage` descending).
2. **Earliest Expiry First**: For candidates with comparable shortages, medicines with earlier expiry dates are prioritized.
3. **Deterministic Tie-Breaking**: Alphabetical ordering on `MedicineName`, `MedicineID`, and `FacilityName` guarantees identical output given identical input datasets.

### Mathematical Transfer Constraints
For any matched source facility $S$ and destination facility $D$:
$$\text{Transfer Quantity} = \min(\text{Surplus}_S, \text{Shortage}_D)$$

**Invariant Rules Enforced:**
* $\text{Transfer Quantity} > 0$ (never negative or zero).
* $\text{Transfer Quantity} \le \text{Surplus}_S$ (never transfer more than source's surplus).
* $\text{Transfer Quantity} \le \text{Shortage}_D$ (never over-supply the destination).
* $S \ne D$ (facilities cannot redistribute to themselves).

---

## 3. TCP Facility Data Ingestion
The engine seamlessly ingests real-time updates received over the in-process multi-threaded TCP server:
$$\text{Wire Format: } \texttt{FACILITY|MEDICINE|BATCH|QUANTITY|TYPE\textbackslash n}$$

Messages are parsed and recorded into thread-safe memory buffers, enabling dynamic redistribution analysis without persistent database overhead.

---

## 4. Advisory Software Disclaimer
> **IMPORTANT NOTICE:**  
> Redistribution recommendations generated by MediSave Edge are advisory decision-support software outputs. The system does not automatically execute physical stock transfers, dispatch transport orders, or modify facility stock without human verification. All clinical decisions remain under the authority of certified pharmacists and medical officers.
